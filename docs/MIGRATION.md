# Руководство по миграции

## v0.8.0 — числа уточнённой теории сдвинулись (осознанно)

Классический тракт (`theory = "classic"`) не изменён ни в одном бите:
замороженные эталоны, case-файлы и снимки классики переносятся как есть.
Изменились числа УТОЧНЁННОЙ теории и поведение контакта — если у вас есть
сохранённые результаты `ktn_linear` / `ktn_full` или собственные допуски,
их придётся пересчитать. Что именно поменялось и почему — CHANGELOG,
раздел `[0.8.0]`; ниже — что делать со своими постановками.

| Что | Было | Стало |
|---|---|---|
| член реакции лицевого условия | `κ_r·D·r` | `κ_r·r` (κ — податливость [м/Па]) |
| член обжатия в лицевых напряжениях | `+ν/(1−ν)·q_n` | `−ν/(1−ν)·q_n` (сжатие) |
| нормировка шага МОР | по срединному прогибу | по лицевому + `κ_r` |
| лицевое условие пары пластин | только кривизный член | полная формула (9) обеих граней, податливости складываются |
| останов итерации Кармана/КТН | норма шага | истинная невязка `‖R(c)‖/‖b‖` |
| топология зоны контакта | граф близости с порогом по медиане шага | решётка квадратуры, 4-связность |
| отбор собственных пар | абсолютный порог над размерными `ω²` | безразмерные пороги над нормированным пучком |

Отдельно, для читателей старых снимков: версия схемы полей `fields.npz`
равна 3 начиная с v0.6.6 (к схеме 2 добавлены мембранные усилия `N` и
эквивалентное напряжение фон Мизеса); в v0.8.0 она не менялась. Перечень
ключей — docs/CASE_SCHEMA.md, раздел про вывод.

**Что сделать.**

1. **Пересчитать уточнённые постановки.** Прежний член реакции зависел от
   системы единиц: при переходе (E, q₀) → (E/s, q₀/s) классика повторялась
   бит-в-бит, а КТН-контакт менялся качественно. Числа после исправления —
   физичные; сравнивать их со старыми снимками бессмысленно.
2. **Проверить свои допуски `verify.tol`.** Итерации Кармана/КТН теперь
   останавливаются по истинной невязке, поэтому «сошедшийся» результат стал
   строже: постановка, раньше проходившая с ложным флагом сходимости,
   потребует большего `karman_max_iter` или `n_load_steps`.
3. **Ожидать отказ там, где раньше был тихий неверный ответ.** Ограда
   `M ≥ N` (узлов квадратуры внутри Ω не меньше числа базисных функций)
   отклоняет постановки, которые прежде молча уходили в МНК; лечится
   увеличением `Q` (или уменьшением `p`). Так же отклоняются
   соприкасающиеся операнды `union` в `compose`, точка `point` вне Ω и
   ключи `[plate2.model]` вне белого списка.
4. **Читать таблицу верификации у контактных задач.** К эталонам
   добавлены ворота инвариантов (`r ≥ 0`, проникание, существование
   контакта, замыкание `∫r = P`), поэтому `verify.reference = "none"`
   больше не означает «проверять нечего»: расходившийся МОР с `r ≡ 0`
   теперь виден.
5. **Читать `Result.warnings`.** Туда попадают деградации факторизации
   (масштабирование Якоби или спектральное псевдообращение вместо
   Холецкого) — они означают, что решалась УСЕЧЁННАЯ задача.

**Новое, чего можно не касаться.** Секция `[model.face_terms]`
(`curvature` / `load` / `reaction`) включает слагаемые лицевого условия по
отдельности; по умолчанию включены все три, и арифметика штатного пути не
меняется. Ключ `[model] karman_anderson` (окно ускорения итерации Пикара)
стал документированным — прежде он читался скрытно.

## v0.5.0 — переименование теорий (`ktn` → `ktn_linear` / `ktn_full`)

С введением ПОЛНОЙ нелинейной теории Кармана–Тимошенко–Нагди значение
`[model] theory = "ktn"` стало неоднозначным: оно означало ЛИНЕЙНЫЕ поправки
сдвига/обжатия постобработкой, а «КТН» — имя полной (теперь нелинейной) теории.
Введены ЯВНЫЕ имена без тихой смены семантики.

| Старое | Новое | Что это |
|---|---|---|
| `theory = "ktn"` | `theory = "ktn_linear"` | линейные поправки сдвига/обжатия (прежнее поведение, **число-в-число**) |
| — (не было) | `theory = "ktn_full"` | полная нелинейная КТН (Карман + сдвиг + обжатие) |

**Обратная совместимость.** `theory = "ktn"` работает как **депрекация-алиас**
на `ktn_linear` (старые case-файлы считают то же, байт-в-байт) и выводит
`DeprecationWarning`. Алиас `ktn` НЕ переведён на `ktn_full` — это тихо сменило
бы результат прежних расчётов. **Алиас будет удалён в v1.0.0.**

### Как обновить case-файл

Было:

```toml
[model]
theory = "ktn"           # неоднозначно
h = 0.06
```

Стало (эквивалентно, без предупреждения):

```toml
[model]
theory = "ktn_linear"    # явно: линейные поправки
h = 0.06
```

Чтобы перейти на ПОЛНУЮ нелинейную теорию:

```toml
[model]
theory = "ktn_full"
inplane_bc = "immovable" # закрепление кромки в плане
h = 0.06
n_load_steps = 4         # большой прогиб — шаги по нагрузке
```

Рамки полной КТН (проверяет валидатор, а не решатель): защемление —
на ЛЮБОЙ R-области, включая неканонические и многосвязные (L, кольцо,
`compose`); мягкий шарнир РЕАЛИЗОВАН (граничный член слабой формы
собирается квадратурой по ∂Ω) и допущен там, где эта квадратура точна —
`circle | ellipse | rectangle | annulus`; область с входящим углом на
мягком шарнире и смешанные краевые условия для `ktn_full` отклоняются
понятной ошибкой. Смешанные КУ доступны у `karman` (стороны
`clamped | hinge`).

### CLI

Флаги `--theory` / `--inplane-bc` принимают новые имена:
`--theory ktn_linear` | `--theory ktn_full`. Устаревшее `--theory ktn` из CLI
исключено (используйте явные имена); алиас `ktn` сохранён только для
case-файлов ради обратной совместимости.

### Программный API

Имена и сигнатуры `ktn.KTNParams` (линейные коэффициенты) и
`ktn.stresses_faces` в v0.5.0 не менялись. Новый первоклассный слой лицевых
величин — `faces.FaceParams` (канонические имена параметров толщины
`h_psi_sq`, `h_star_sq`, `h_c_sq`). Полный нелинейный решатель —
`ktn_full.KTNPlate`.

Внимание: СОДЕРЖИМОЕ этих формул позже поправлено — `contact_displacement`
и `corrected_deflection` считают член реакции как `κ_r·r`, а
`stresses_faces` даёт обжатие со знаком сжатия (см. раздел про v0.8.0
выше). Обе функции получили необязательный аргумент `terms`
(`faces.FaceTerms`) — переключатели слагаемых лицевого условия; значение
по умолчанию `None` означает «все слагаемые включены» и сохраняет прежний
путь вычисления.
