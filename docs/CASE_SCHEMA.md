# CASE_SCHEMA — схема case-файла

Case-файл — TOML-описание постановки задачи: геометрия, закрепление,
нагрузка, модель, контакт, дискретизация, верификация, вывод. Загружается
`plate_solver.problem.Problem.from_toml`, решается `dispatch.solve(problem)`.
Новый случай = копия шаблона (`plate-solve --new <kind>`) и правка
нескольких строк — см. пример внизу.

Правило дефолтов: физика и дискретизация по умолчанию живут в ОДНОМ месте —
`plate_solver.config.Config`; отсутствующий ключ означает «взять дефолт
Config», а не «второй экземпляр дефолта в схеме».

## Схема

Секции: `[geometry]`, `[bc]`, `[load]` — **обязательные**;
`[model]`, `[contact]`, `[discretization]`, `[verify]`, `[output]` —
необязательные. Секция `[eigen]` (собственная задача, v0.6.4) — АЛЬТЕРНАТИВА
изгибу/контакту: при её наличии `[load]`/`[contact]`/`[plate2]` не нужны и
запрещены (анализ линейный, без поперечной нагрузки). Неизвестные секции и ключи отклоняются с ошибкой
(защита от опечаток). Ошибки валидатора имеют вид
«ключ: получено X, ожидалось Y, см. docs/CASE_SCHEMA.md#секция».

## Полный аннотированный пример

```toml
# Кольцо под равномерной нагрузкой, защемление, сверка с аналитикой и 1D.

[geometry]
kind = "annulus"        # circle | rectangle | L | annulus | compose
a = 1.0                 # внешний радиус
b = 0.4                 # внутренний радиус (0 < b < a)

[bc]
type = "clamped"        # soft_hinge | clamped | mixed (стороны — [[bc.sides]], #bc)

[load]
type = "uniform"        # uniform | patch | point
q0 = 4.0                # равномерная поперечная нагрузка (q0 > 0 «вниз»)

[model]
theory = "classic"      # classic | karman | ktn_linear | ktn_full (§model);
                        #   устаревший алиас "ktn" = ktn_linear (DeprecationWarning)
# E = 2.1e6             # дефолты Config: E=2.1e6, nu=0.3, h=1.0
# nu = 0.3
h = 0.06                # толщина (важно для ktn_linear/ktn_full)
# --- только для НЕЛИНЕЙНЫХ теорий (karman, ktn_full) --- #
# inplane_bc = "immovable"  # immovable (u=v=0) | movable (N·n=0)
# n_load_steps = 1          # шагов по нагрузке (большой прогиб — увеличить)
# karman_relax = 1.0        # недорелаксация θ ∈ (0, 1] итерации Пикара
# karman_max_iter = 200     # предел итераций Пикара на уровень нагрузки
# karman_tol = 1.0e-8       # относит. порог останова ‖Δw‖/‖w‖
# karman_method = "picard"  # picard | newton (только karman)
# ktn_method = "picard"     # picard | newton (только ktn_full)

[discretization]
p = 10                  # степень Чебышёва по оси (N = (p+1)²); дефолт 12
Q = 1024                # узлов Гаусса–Лежандра по оси; дефолт 64
# grid_n = 80           # фоновая сетка вывода

[verify]
reference = "analytic"  # analytic | mms | fem | none
cross_1d = true         # сверка с 1D-Ритцем по радиусу (только circle/annulus,
                        # равномерная нагрузка)
tol = 1.0e-2            # допуск ворот верификации
model_gap = false       # печатать строку «истинный Кирхгоф» (вне допуска)

[output]
dir = "results/annulus_clamped"
figures = true
```

Требование к зонам (`load.zone`, `contact.zone`, пятно `point`): пересечение
зоны с Ω должно накрывать **не менее 20 узлов квадратуры**, иначе интеграл по
маске теряет смысл. Для `point` пятно расширяется автоматически до
наименьшего радиуса с ≥ 20 узлами (факт и новое eps — в `result.json`,
поле `warnings`); для `patch` авторасширение зоны произвольной формы не
определено — это ошибка с советом «увеличьте Q или зону».

## Несовместимости

| Комбинация | Решение |
|---|---|
| theory = ktn_full + bc.type = soft_hinge + kind ∉ {circle, ellipse, rectangle, annulus} | ошибка: граничный член §3.5 — квадратура ∂Ω; область с входящим углом (L/compose) — v0.7 |
| contact.enabled + theory = ktn_full/karman + bc = soft_hinge + kind ∉ {circle,ellipse,rectangle,annulus} | ошибка: контакт на шарнире — без входящего угла (§4); пара на шарнире (звёздная область) ПОДДЕРЖАНА (v0.6.5) |
| contact.enabled + theory = ktn_full/karman + load.type ∉ {uniform, gaussian, expr} | ошибка; гладкое ПОЛЕ нагрузки допущено в ПОЗИЦИОННОМ основании (v0.7.0, ворота — tests/test_contact_field_load.py); силовой/парный контакт — только uniform (§4) |
| contact.force + target = plate2 + классическая пара | ошибка: силовое управление парой — только нелинейная пара karman \| ktn_full (v0.6.5); для неё force = суммарное усилие прижатия ∫r, ищется начальный зазор z (z < 0 — натяг); рабочая область — умеренное прижатие (глубокий натяг — понятный отказ) |
| contact.scheme / contact.gain без нелинейного контакта | ошибка: ключи осмысленны только при theory = karman/ktn_full + contact |
| verify.reference = analytic + geometry.kind = compose | ошибка: используйте mms \| fem \| none |
| verify.cross_1d + неосесимметричная постановка | ошибка: cross_1d — только circle/annulus с равномерной нагрузкой |
| verify.reference ≠ none + {load.expr, load.thermal_moment, [supports], model.h_expr, contact.gap_expr, [model.orthotropy], load.type = line} | ошибка: реестр эталонов не учитывает ключи v0.7.0 — сравнение дало бы ложный вердикт; ворота — tests/test_*.py |
| verify.reference = mms + model.winkler > 0 | ошибка: MMS-эталон не учитывает основание (ложный FAIL); reference = none либо k_w = 0 |
| load.type = line + КТН-теории / контакт / [plate2] / mixed | ошибка с советом — см. #load (expr, напротив, принимается всеми теориями, контактом-основанием и [plate2]; для expr действует лишь запрет verify.reference ≠ none) |
| [supports] + {soft_hinge классики, КТН-теории, prestress, model.h_expr, thermal_moment} | ошибка с советом — см. #supports (ортотропия, Винклер и КЛАССИЧЕСКИЙ позиционный контакт на clamped — СОВМЕСТИМЫ, v0.7.0) |
| [model.orthotropy] + {нелинейные теории, КТН, контакт, free-стороны mixed, thermal_moment, model.h_expr} | ошибка с советом — см. #model (Винклер и опоры — СОВМЕСТИМЫ, v0.7.0) |
| load.exact = true + {soft_hinge классики, КТН-теории, mixed, контакт, [plate2]} | ошибка с советом — см. #load (точная δ — только classic clamped и karman) |
| model.h_expr + {КТН-теории, шарнир/mixed, контакт, [eigen], movable} | ошибка с советом — см. #model |
| load.thermal_moment + {КТН-теории, mixed, контакт, [plate2], [eigen], не-uniform нагрузка} | ошибка с советом — см. #load |

Классический контакт (`theory = classic`, `ktn_linear`) работает при `soft_hinge`
И `clamped` (об основание, штамп, пара пластин). Историческое ограничение
«контакт только при мягком шарнире» (v0.2) снято. ОГОВОРКА для
`ktn_linear + contact` при ТОЛСТОЙ пластине (h ≳ 0.5): лицевое условие
несёт член `c_r·D·r`, усиление которого β-нормировка классического отклика
не учитывает — МОР может зациклиться (2-цикл, r ≡ 0 — свободное решение);
несходимость честно попадает в предупреждения result.json (v0.7.0) —
при таком предупреждении уменьшайте `beta` либо толщину/теорию.

## geometry

Шесть видов области. `circle` — круг радиуса `a` с центром в начале координат;
`rectangle` — `[x1, x2] × [y1, y2]`; `L` — квадрат `side` с квадратным
вырезом `cut` (входящий угол); `annulus` — кольцо `b < r < a`;
`ellipse` — эллипс с полуосями `a` (по x) и `b` (по y), центр (0,0)
(при `a = b` — круг; аналитического эталона нет ⇒ `verify.reference = none | fem`);
`compose` — конструктор (см. #compose). Граница всюду задаётся R-функцией
ω(x, y): ω > 0 внутри, ω = 0 на границе.

Замечание по контакту на эллипсе: ВСЕ теории допускают `clamped` И `soft_hinge`
(эллипс — звёздная область, граничный член §3.5 полной КТН собирается; в т.ч.
нелинейный контакт и пара, см. §model, §contact). `ellipse` — вид
ВЕРХНЕГО уровня, не примитив `compose` (ограда compose-языка неизменна).

## compose

Дерево операций над примитивами (ограда v0.2 — не расширяется):
операции `union | intersect | difference` (difference строго бинарна),
примитивы `circle (a, cx, cy)` и `rectangle (x1, x2, y1, y2)`,
глубина дерева ≤ 3 (узлы считаются по вертикали, примитив = 1),
всего ≤ 7 узлов. bbox: union — объединение, intersect — пересечение,
difference — bbox первого операнда.

```toml
[geometry]
kind = "compose"

[geometry.tree]             # квадрат с круглым вырезом
op = "difference"

[[geometry.tree.children]]
kind = "rectangle"
x1 = 0.0
x2 = 1.0
y1 = 0.0
y2 = 1.0

[[geometry.tree.children]]
kind = "circle"
a = 0.2
cx = 0.5
cy = 0.5
```

## bc

Один тип закрепления на всю границу: `soft_hinge` — «мягкий шарнир»
(M = 0 на ∂Ω, расщепление бигармоники на две задачи Пуассона, plate.py);
`clamped` — жёсткое защемление (структура w = ω²Φ, прямой Ритц, clamped.py).
Смешанные закрепления по участкам — `mixed` + `[[bc.sides]]` (только
kind = rectangle): каждой стороне x1|x2|y1|y2 назначается тип
`clamped` (w = ∂w/∂n = 0, множитель ω² в структуре), `hinge`
(w = 0, истинный шарнир: M_n = 0 естественно из полной билинейной формы)
или `free` (СВОБОДНЫЙ край: кинематических условий нет; M_n = 0 и
обобщённая перерезывающая Кирхгофа V_n = 0 — естественные условия).
Правило жёстких смещений: набор сторон обязан исключать ядро {1, x, y} —
не менее ОДНОЙ clamped либо не менее ДВУХ hinge; FFFF и SFFF отклоняются
валидатором. Теории: `classic` (линейный Кирхгоф, v0.3; стороны clamped |
hinge | free) и **`karman`** (геометрически-нелинейный, v0.6.5 — структура
`∏(сторона)^{2|1}·Φ` + мембранная связь Фёппля–Кармана; линейный предел
совпадает с классическим рядом Леви машинно; стороны только clamped | hinge —
free-стороны нелинейной теории не верифицированы и отклоняются, аудит v0.6.5).
`ktn_full` со смешанными КУ (граничный член §3.5 на шарнирных сторонах) и
КОНТАКТ при mixed — направление развития v0.7+ (валидатор отклоняет
с пояснением).

```toml
[bc]
type = "mixed"
[[bc.sides]]
side = "x1"
type = "clamped"   # консоль: заделка x1, остальные free
[[bc.sides]]
side = "x2"
type = "free"
[[bc.sides]]
side = "y1"
type = "free"
[[bc.sides]]
side = "y2"
type = "free"
```

## load

`uniform` — равномерная `q0` по всей Ω. `patch` — `q0` внутри зоны
`[load.zone]` (геометрия зоны — тем же языком, что `[geometry]`), ноль вне:
`q̃ = q0·[ω_zone > 0]`. `point` — сосредоточенная сила `P` в точке
`(x0, y0)` как регуляризованный patch: круговое пятно радиуса `eps`,
`q = P/(π·eps²)`; дефолт `eps = 0.05·min(ширина, высота bbox)`.
`gaussian` — гладкая локализованная `q = q0·exp(−r²/(2σ²))` (центр `x0, y0`,
ширина `sigma`): у неё `Δq` аналитична, поэтому проявляется член КТН
`−h_*²Δq` (`theory = ktn_full`) — под НЕравномерной нагрузкой уже и СРЕДИННЫЙ
прогиб КТН отличается от классики (в отличие от равномерной, где `Δq = 0`);
эффект растёт с сужением `sigma`. Для `patch`/`point` (разрывная `q`) член
`−h_*²Δq` опускается с пометкой в предупреждениях.

`expr` (v0.7.0) — произвольная ГЛАДКАЯ нагрузка выражением:
`q = q0·g(x, y)`, где `g` — строка `expr`. Белый список (ограда безопасности,
не расширять бездумно): имена `x, y, pi, sin, cos, tan, exp, log, sqrt, abs,
tanh, min, max`, числа (включая `2.5e-3`), операции `+ − * / **`, скобки и
запятая; всё прочее (строки, атрибуты, индексация…) — отказ при чтении case.
Для гладкого `g` член КТН `−h_*²Δq` берётся СИМВОЛЬНЫМ дифференцированием
(точный `Δq`, как у `gaussian`); для негладких (`abs`/`min`/`max`) член
опускается с пометкой. Выражение обязано быть конечным и вещественным в
УЗЛАХ КВАДРАТУРЫ (проверка узловая: полюс, попавший МЕЖДУ узлами, даст
большие конечные значения без отказа); ответственность за гладкость на
пользователе — резкие фронты (крутой `tanh`) снижают точность квадратуры
(ширина фронта ≳ шага узлов). Ресурсная ограда: длина ≤ 20000 символов,
целые литералы ≤ 12 цифр, целый показатель степени ≤ 64, башни `a**b**c`
запрещены.

```toml
[load]
type = "expr"
q0 = 4.0
expr = "sin(pi*x/2.0)*sin(pi*y/1.2)"
```

`line` (v0.7.0) — ЛИНЕЙНАЯ (погонная) нагрузка вдоль отрезка `p0`–`p1`:
линейный функционал `b_i = intensity·∫_seg ψ_i ds` (1D Гаусс по отрезку —
машинно точен; полная сила = intensity·|p1−p0|). Тракты: `classic`
(clamped | soft_hinge, любые R-области) и `karman`; КТН-теории (`Δq` линии
сингулярен), контакт, пара и `mixed` — отказ. ЧЕСТНАЯ ОГОВОРКА о точности:
скачок перерезывающей силы `[Q_n] = −intensity` поперёк линии делает
сходимость Ритца АЛГЕБРАИЧЕСКОЙ (~p⁻³ по прогибу, измерено ~p⁻²·⁸):
рекомендуется `p ≥ 20` (при p=12 ошибка ~0.3%); профиль перерезывающих Q
поперёк линии в спектральном базисе «звенит» (Гиббс на скачке) — поля w и M
корректны. Отрезок обязан лежать в Ω (концы на границе допустимы; целиком
на границе — отказ: там ψ ≡ 0). Эталон — ряд Навье `ladder.navier_line`
(tests/test_line_load.py).

```toml
[load]
type = "line"
p0 = [1.0, 0.0]
p1 = [1.0, 1.2]
intensity = 1.0
```

### Термоизгиб (v0.7.0)

`thermal_moment = M_T` (только при `type = "uniform"`; `q0 = 0` — чистый
термоизгиб): `D·Δ²w = q − ΔM_T`, полные моменты несут сдвиг `−M_T`.
Конвенция: `M_T = αEΔT·h²/(12(1−ν))` для линейного перепада `ΔT` по толщине
(множитель `1/(1−ν)` уже включён). Свойства и честные оговорки:

* ЗАЩЕМЛЕНИЕ не гнётся константным `M_T` (классика Boley–Weiner): прогиб
  бит-точно прежний, сдвигаются только моменты;
* ИСТИННЫЙ шарнир — `theory = "karman"` (полная билинейная форма даёт
  естественное `M_n = −M_T`): на круге — точная сфера
  `w = M_T(a²−r²)/(2D(1+ν))` (машинная верификация);
* `classic` + `soft_hinge` — модель РАСЩЕПЛЕНИЯ: на прямых кромках совпадает
  с истинным SS, на КРИВОЙ границе даёт модельное `M_T(a²−r²)/(4D)` —
  отличие от истинного SS в `2/(1+ν)` раза (≈1.54 при ν=0.3; аналог
  документированного парадокса мягкого шарнира) — для кривых границ
  используйте `theory = karman`;
* термо-мембранная сила `N_T` НЕ моделируется (средняя температура срединной
  плоскости нулевая) — термо-выпучивания нет, `[eigen]` с термо — отказ.

```toml
[load]
type = "uniform"
q0 = 0.0
thermal_moment = 3.0
```

### Точечная сила: пятно и точная δ (exact, v0.7.0)

По умолчанию `point` — регуляризованное пятно `q = P/(π·eps²)`.
`exact = true` включает ИСТИННУЮ δ-силу: `b_i = P·ψ_i(x0, y0)` — точечное
вычисление ограничено на H² в 2D, дискретизация точная (без квадратуры и
пятна). Граница применимости строгая (уточнение NOTES §18, где δ была
исключена целиком): точная δ доступна ТОЛЬКО в трактах с прямой сборкой —
`classic` clamped и `karman` (clamped | soft_hinge, полная форма);
расщепление классического шарнира ((P1) с δ — функционал вне H¹) и
КТН-теории (прогиб под δ логарифмически расходится) — отказ. Эталоны —
классика: `w(0) = P·a²/(16πD)` (защемлённый круг, + полный профиль Грина)
и `(3+ν)/(1+ν)·P·a²/(16πD)` (истинный шарнир); сходимость по базису
алгебраическая ~p⁻¹·⁵ в точке приложения (tests/test_point_exact.py).

```toml
[load]
type = "point"
P = 10.0
x0 = 0.0
y0 = 0.0
exact = true
```

### Неравномерная нагрузка

Через схему доступны `patch`, `point` (пятно или точная δ — выше) и `expr`
(v0.7.0, гладкая — выше). Произвольная
гладкая f(x, y) доступна и через API, значениями в узлах квадратуры:

```python
from plate_solver import Config
from plate_solver.geometry import make_circle
from plate_solver.plate import PlateBending

pb = PlateBending.from_config(make_circle(1.0), Config(p=10, Q=256))
q = pb.quad
f_values = 4.0 * (1.0 + 0.5 * q.x)        # свой закон нагрузки в узлах
cM, cw = pb.solve(f_values)
print(float(pb.deflection(cw, 0.0, 0.0)))
```

## model

Лестница теорий одним ключом `theory` — с ЧЕСТНЫМИ, однозначными терминами
(нельзя называть линейную поправку именем полной нелинейной теории):

* `classic` — линейная теория Кирхгофа (расщепление бигармоники);
* `karman` — геометрически-**НЕЛИНЕЙНОЕ** решение Фёппля–Кармана: прогиб
  входит квадратично в мембранные деформации, поле усилий `N` ужесточает
  пластину (мембранная связь `L(Φ, w)`). Итерация Пикара по замороженным
  усилиям `N_k` с наращиванием нагрузки (`membrane.py`, `THEORY.md`);
* `ktn_linear` — **ЛИНЕЙНЫЕ** поправки поперечного сдвига/обжатия (часть теории
  Тимошенко–Нагди) ПОСТОБРАБОТКОЙ на решении Кирхгофа (`corrected_deflection`
  при r = 0; кривизна как Δw = −M/D, без численного дифференцирования). Это НЕ
  нелинейная теория (прежнее поведение `ktn`, число-в-число);
* `ktn_full` — **ПОЛНАЯ нелинейная КТН**: Карман + регуляризация связи
  `(I − h_ψ²Δ)L(Φ, w)` + нагрузочный член `−h_*²Δq_n` (`ktn_full.py`, §THEORY).

**Депрекация `ktn`.** Значение `ktn` неоднозначно и переименовано: `ktn` —
устаревший алиас на `ktn_linear` (сохраняет поведение старых case-файлов,
число-в-число) с `DeprecationWarning`; будет удалён в v1.0.0. Миграция —
`docs/MIGRATION.md`.

**Только для НЕЛИНЕЙНЫХ теорий (`karman`, `ktn_full`).** `inplane_bc` —
закрепление кромки В ПЛАНЕ: `immovable` (u = v = 0 на ∂Ω — кромка не
втягивается, натяжение максимально; основной режим) либо `movable` (N·n = 0 —
кромка свободна в плане, эффект слабее). Параметры итерации: `n_load_steps`
(шагов по нагрузке; тёплый старт по уровням), `karman_relax` (недорелаксация
θ ∈ (0, 1]), `karman_max_iter`, `karman_tol` (относительный останов ‖Δw‖/‖w‖);
метод — `karman_method` (только `karman`) / `ktn_method` (только `ktn_full`),
оба `picard` по умолчанию | `newton`. `newton` — согласованный касательный
оператор `J = dR/dc` (аналитический) с защитой линейным поиском: КВАДРАТИЧНАЯ
сходимость (~5–7 итераций вместо десятков/сотен у Пикара, слабо зависит от
уровня нагрузки), даёт то же решение; полезен на тонких пластинах, где Пикар
сходится медленно. При `classic`/`ktn_linear` задание любого
из этих ключей — ошибка постановки. Рамки: любые R-области (круг, прямоугольник,
L, кольцо, compose); изгибные КУ `clamped`/`soft_hinge`. Полная КТН (`ktn_full`)
на мягком шарнире отличается от защемления граничным членом слабой формы §3.5
(квадратура ∂Ω) и реализована для `circle`/`ellipse`/`rectangle`/`annulus`
(область с входящим углом L/compose — v0.7). Контакт для нелинейных теорий:
одиночная пластина — на защемлении (любая R-область) ИЛИ мягком шарнире
(вышеуказанные формы), позиционный ИЛИ силовой (`force`); пара — защемление
ЛИБО мягкий шарнир (звёздные формы), позиционная ЛИБО силовая (`force` —
прижатие ∫r = P, v0.6.5); нагрузка — равномерная (позиционное основание —
также gaussian | expr, v0.7.0), см. §contact.

**CLI-переопределение.** Флаги `plate-solve`/`plate-verify` `--theory`
(`classic | karman | ktn_linear | ktn_full`) и `--inplane-bc`
(`immovable | movable`) переопределяют блок `[model]` — удобно гонять одну
постановку разными теориями
(`--inplane-bc` — только вместе с `--theory karman`).

### Ортотропия (v0.7.0)

Подсекция `[model.orthotropy]` включает ОРТОТРОПНУЮ классическую теорию:
энергия `U = ½∫[D11·w_xx² + 2·D12·w_xx·w_yy + D22·w_yy² + 4·D66·w_xy²]`
собирается ПОЛНОЙ квадратичной формой по вторым производным структуры.
РОВНО один набор: инженерный `Ex, Ey, nu_xy, Gxy` (конвенция
`ν_yx = ν_xy·Ey/Ex`; конверсия `k = 1 − ν_xy·ν_yx`, `D11 = Ex·h³/(12k)`,
`D22 = Ey·h³/(12k)`, `D12 = ν_xy·Ey·h³/(12k)`, `D66 = Gxy·h³/12` — толщина
из `[model] h`) либо прямой `D11, D12, D22, D66` (эллиптичность:
`D11, D66 > 0`, `D11·D22 > D12²`). Ключи `E`/`nu` рядом запрещены
(двусмысленность источника жёсткости).

Честный объём: `theory = classic` — изгиб на `clamped` (любая R-область) и
`mixed` clamped|hinge (прямоугольник; all-hinge = SSSS с сильным эталоном
Лехницкого, машинная сходимость), собственные задачи (`[eigen]`: частоты и
выпучивание против формул Лехницкого/Лейссы); `theory = karman` (v0.7.0) —
ОРТОТРОПНЫЙ Карман: мембранный закон `N = A·ε` (A11 = Ex·h/k и т.д.) требует
ИНЖЕНЕРНОГО набора (прямой D-ввод отклоняется — A неопределима), только
`immovable`, КУ clamped|soft_hinge; сертификат — редукционная лестница
(линейный предел = классическая ортотропия БИТ-ТОЧНО, изотропная редукция в
НЕЛИНЕЙНОМ режиме машинно 1.4e-16, знак мембранного ужесточения,
Пикар = Ньютон 6e-10 — согласованный касательный с ортотропной ∂N/∂c). Моменты — ортотропный
конститутив (`Mx = −(D11·w_xx + D12·w_yy)` и т.д.), `Qx/Qy` — равновесие
(наследуется). Совместимы (v0.7.0): основание Винклера (свёртка +k_w∫ψψ
конститутив-независима; сертификаты — MMS c k_w машинно и сдвиг частот
`ω² = π⁴·D_mn + k_w`) и точечные опоры (тождество Шермана–Моррисона на
ортотропном операторе — машинное; монотонность частот). Отказы:
`soft_hinge` классики (расщепление предполагает
изотропный `Δ²`), нелинейные теории и КТН (нужна ортотропная мембранная
жёсткость / изотропный 3D-закон поправок), контакт,
`verify.reference` (реестр эталонов изотропен), free-стороны mixed. На
КРУГЛОЙ границе изотропная редукция сходится квадратурно (~1e-5 при Q=64 →
~1e-6 при Q=128, след нуль-лагранжиана маски) — литературных ортотропных
эталонов на круге в реестре нет, ворота — редукция + сходимость.

```toml
[model]
theory = "classic"
h = 1.0

[model.orthotropy]
D11 = 2.0
D12 = 0.5
D22 = 1.0
D66 = 0.4
```

### Переменная толщина (v0.7.0)

`h_expr = "выражение h(x, y)"` (вместо скаляра `h`; белый список — как у
`load.expr`): жёсткости `D(x, y) = E·h³/12(1−ν²)` и `C(x, y) = E·h/(1−ν²)`
входят ВЕСАМИ сборки. При `D ≠ const` гауссов член НЕ нуль-лагранжиан,
поэтому сборка идёт ПОЛНОЙ билинейной формой (упрощённый `∫D·ΔψΔψ` был бы
неверен). Честный объём: `classic` (clamped, любая R-область) и `karman`
(clamped, immovable). Моменты и напряжения — с ЛОКАЛЬНОЙ `D(x, y)`/`h(x, y)`
(`fields.npz` дополнительно несёт `h_grid`). Сертификат — MMS сильной формы
`q = (D(w_xx+νw_yy))_xx + (D(w_yy+νw_xx))_yy + 2((1−ν)D·w_xy)_xy`
(спектральная сходимость; на кривой границе — пол маскированной квадратуры,
общий с постоянной толщиной). Отказы: КТН-теории (лицевые параметры стали бы
полями), шарнир/смешанные КУ, контакт, собственные задачи, movable, термо,
опоры, ортотропия; `h ≤ 0` где-либо на Ω (проверка на сетке 97² + в узлах
квадратуры: провал `h ≤ 0` УЖЕ шага сетки может проскочить — ответственность
постановки); предупреждение при контрасте `h_max/h_min > 3`
(обусловленность ~ контраст³). Требование Кирхгофа (`h/L` мал, `|∇h|` мал)
решателем не контролируется — ответственность постановки.

```toml
[model]
theory = "classic"
h_expr = "0.5*(1 + 0.3*x + 0.2*y)"
```

## contact

Односторонний контакт с жёстким ПЛОСКИМ препятствием при постоянном зазоре
Δ (метод обобщённой реакции). Зона препятствия `[contact.zone]` — тем же
геометрическим языком; дефолт — вся Ω (основание), подобласть — плоский
штамп. Ровно одно из `gap` (абсолютный Δ) / `gap_factor`
(Δ = gap_factor·w_free; w_free считает диспетчер). Критерий останова
`stop`: `dr` — ‖r_k − r_{k−1}‖ < tol; `comp` — безразмерная KKT-невязка
Синьорини < tol (см. докстринг `ContactMOR.solve`).

### Поле зазора Δ(x, y) (v0.3; gap_expr — v0.7.0)

Вместо скаляра зазор задаётся таблицей `[contact.gap]` (ровно одно из:
`gap`, `gap_factor`, `[contact.gap]`, `gap_expr`): `const` (алиас скаляра),
`plane` (наклонное основание), `paraboloid` (неплоский штамп: apex — зазор в
вершине, r_curv — радиус кривизны), `steps` (base + `[[contact.gap.zones]]`
— несколько штампов разной высоты; зоны применяются по порядку, зазор в
зоне = value). Положительность Δ на основании проверяет диспетчер.
Для отчёта (`Result.delta`) у поля берётся min Δ на основании; той же
величиной нормируются метрики комплементарности.

`gap_expr` (v0.7.0) — произвольный профиль ВЫРАЖЕНИЕМ (строка-ключ в
`[contact]`, без TOML-ловушки таблицы): `Δ = f(x, y)`, белый список — как у
`load.expr` (см. #load). Константное выражение редуцируется в скаляр и идёт
путём скалярного `gap` бит-точно; при `force` — форма штампа (как
`[contact.gap]`); маршрутизируется во все контактные тракты (линейный,
нелинейный МОР+КТН, пара, силовой):

```toml
[contact]
enabled = true
gap_expr = "5.0e-3 + ((x-1.0)**2 + (y-0.6)**2)/(2*3.0)"   # параболический штамп
```

Произвольное поле доступно и через API, по образцу нагрузки:

```toml
[contact]
enabled = true

[contact.gap]
kind = "paraboloid"      # штамп-параболоид
r_curv = 1.0e4
apex = 1.0e-4            # зазор в вершине (cx = cy = 0 по умолчанию)
```

```python
mor = ContactMOR(pb, cfg, gap=gap_values)   # gap_values — массив в узлах квадратуры
```

### Силовой штамп (v0.3)

`force = P` (> 0): задана равнодействующая реакции, уровень штампа ищется
из скалярного уравнения `∫r dΩ = P` (монотонного по уровню; brentq на
[касание, отрыв] с тёплым стартом МОР). Скалярные `gap`/`gap_factor` при
`force` игнорируются (warning в result.json); таблица `[contact.gap]`
осмыслена как ФОРМА штампа относительно искомого уровня:
Δ(x, y) = level + shape(x, y). `Result.level` — найденный уровень,
`Result.force_total` — фактическая ∫r. P выше достижимого максимума
(касание) — ошибка с указанием диапазона. Точность замыкания
позиционной и силовой постановок требует сходимости МОР (tol достижим,
а не «по лимиту итераций») — см. tests/test_force_stamp.py.

### Нелинейный контакт МОР+КТН (v0.6.3)

При `theory = karman | ktn_full` контакт маршрутизируется в
`contact_nl.NonlinearContactMOR` — метод обобщённой реакции ВОКРУГ полного
нелинейного решателя КТН (единый `KTNSolver`). Условие непроникания ставится
на ЛИЦЕВОЙ поверхности (условие Синьорини на грани):
`u_c = w + (h_c²−h_*²)Δw ≤ z`. Коэффициент кривизны масштабируется теорией: у
`karman` он НОЛЬ (контакт по срединной), у `ktn_full` — физическая лицевая
кривизна (подпись КТН: сглаживание реакции сдвигом/обжатием). Рамки тракта:
защемление (`bc = clamped`, любая R-область) ИЛИ мягкий шарнир (`bc = soft_hinge`,
`circle`/`ellipse`/`rectangle`/`annulus` — граничный член §3.5, квадратура ∂Ω);
нагрузка: позиционное ОСНОВАНИЕ принимает uniform | gaussian | expr (полевая
нагрузка, v0.7.0 — tests/test_contact_field_load), силовой режим и пара —
только uniform; позиционный штамп/основание ЛИБО силовой (`force = P`:
уровень ищется из `∫r = P`, brentq поверх нелинейного решателя — одиночная
пластина). На мягком шарнире сильное мембранное ужесточение ⇒ рекомендуется
`gain = "linear"`. Ключи:

* `scheme = nested | merged` (§4.2): `merged` (совмещённый, быстрый, дефолт) —
  один шаг Пикара на шаг МОР; `nested` (вложенный, эталон корректности) — полный
  сходящийся КТН на каждой итерации МОР (дороже);
* `gain = secant | linear` (§4.1): нормировка усиления оператора (теорема 4).
  `secant` (дефолт) — секущая податливость свободного нелинейного решения
  (быстрее); `linear` — линейная податливость (верхняя грань ‖G‖ ⇒ сходимость
  гарантирована, итераций больше — при сильном мембранном ужесточении).

Эталонов контакта в литературе нет: корректность — инварианты (r ≥ 0,
комплементарность, зона) и редукции (зазор → ∞ ⇒ r ≡ 0; уточнение → 0 ⇒
кармановский контакт), см. tests/test_contact_ktn.py и tests/test_contact_nonlinear.py.

```toml
[model]
theory = "ktn_full"
h = 0.2

[contact]
enabled = true
gap_factor = 0.5         # Δ = 0.5·w_free — частичная зона
scheme = "merged"
gain = "secant"
```

## supports

Точечные упругие опоры (v0.7.0): энергия пружин `(k/2)·Σ_j w(P_j)²` входит
в изгибную жёсткость ранг-1 добавками `k·ψ(P_j)ψ(P_j)ᵀ` ДО факторизации
(паттерн Винклера) — работает в изгибе (`classic` clamped/mixed, `karman`
все КУ) и в собственных задачах (частоты монотонно растут, Курант–Фишер).
Жёсткая опора — штраф: при `k ≈ 1e6·D/a³` ошибка штрафа ~5e-5 (точный закон
`R(k) = w_free(P)/(G_N(P,P) + 1/k)`); при `k ≳ 1e8·D/a³` — предупреждение
(риск потери положительной определённости, МНК-fallback). Реакции
`R_j = k·w(P_j)` — в result.json (`support_reactions`).

```toml
[supports]
points = [[0.0, 0.0], [0.5, 0.0]]   # координаты опор (внутри области!)
stiffness = 2.0e5                    # жёсткость каждой пружины
```

ЧЕСТНАЯ ОГОВОРКА о точности: решение с точечной опорой сходится по базису
АЛГЕБРАИЧЕСКИ ~p⁻² (функция Грина ~r²·ln r у опоры), не спектрально:
реакция при дефолтных p=12/Q=64 несёт ~1% погрешности (эталон π·q·a²/4 —
tests/test_supports.py); худший случай — `point`-нагрузка НАД опорой
(две особенности рядом, погрешность реакции до ~15% при p=12 — поднимайте p
и контролируйте сходимость). С v0.7.0 опоры совместимы с КЛАССИЧЕСКИМ
позиционным контактом об основание на `clamped` (опора в S до факторизации ⇒
оператор SPD, теорема 4 как есть; МОР с опорой у кромки зоны полусходится —
числа стабильны, несходимость честно попадает в предупреждения). Отказы: `soft_hinge` классики (расщепление — ранг-1
вставить некуда; совет: mixed all-hinge или karman), КТН-теории (реакция —
δ-сила, NOTES §18), НЕЛИНЕЙНЫЙ/силовой/парный контакт и преднапряжение
(не верифицированы; классическое позиционное основание на clamped —
поддержано, см. выше), точка вне
Ω или на границе (там ψ ≡ 0 — опора на кромке уже в КУ).

## plate2

Контакт двух пластин (v0.3): `contact.target = "plate2"` + секция `[plate2]`
(bc и load обязательны; geometry/model/discretization по умолчанию — от
первой пластины). Зазор между пластинами — те же `gap`/`[contact.gap]`
(`gap = 0.0` — касание). Итерация МОР на разности прогибов
`r ← [r + β((w₁−w₂) − Δ)]₊`, нагрузки `q₁ − r` и `q₂ + r`;
сходимость — теорема 4 с G = G₁ + G₂. Узлы контакта — квадратура первой
пластины на пересечении планформ (ω₂ > 0); межсеточного переноса нет:
прогиб второй вычисляется в узлах первой прямо через её структуру, вклад
реакции в нагрузку второй интегрируется по родной квадратуре реакции.
Контактное условие пары при `theory = classic` — КЛАССИЧЕСКОЕ (по срединным
плоскостям); геометрически при этом контактируют нижняя лицевая ВЕРХНЕЙ пластины
и верхняя лицевая НИЖНЕЙ. Канон напряжений (§19, NOTES): у верхней пластины
реакция приходит на нижнюю грань (q⁻₁ = r), у нижней — на верхнюю (q⁺₂ = r);
fields.npz содержит обе шестёрки σ (вторая — с суффиксом «2»).

**Нелинейная пара МОР+КТН (v0.6.3; расширена v0.6.5).** При
`theory = karman | ktn_full` (ОБЕ пластины — одна нелинейная теория) пара
маршрутизируется в `contact_nl.NonlinearTwoPlateMOR`: реакция определяется
СОВМЕСТНО двумя нелинейными решателями, условие непроникания — на ЛИЦЕВЫХ
прогибах `u_c1 − u_c2 ≤ z` (§9.2). Требуется ОБЩАЯ квадратура (одна планформа,
один Q) и равномерная нагрузка обеих пластин. Кромки: защемление (любая
R-область) либо МЯГКИЙ ШАРНИР (звёздные circle/ellipse/rectangle/annulus;
`[plate2.bc]` уважается, v0.6.5). СИЛОВОЕ управление парой (`force = P`,
v0.6.5): P — суммарное усилие прижатия ∫r; ищется НАЧАЛЬНЫЙ зазор `z`
(`z < 0` — натяг) продолжением по `z` с тёплым стартом + brentq;
`Result.force_total`/`Result.level` заполняются. Рабочая область — умеренное
прижатие (`z*` вблизи касания); глубокий натяг — понятный отказ с советом
уменьшить `force`. Смешанные (`{classic, ktn_full}`) и `ktn_linear` пары —
направление развития v0.7.

```toml
[contact]
enabled = true
target = "plate2"
gap = 0.0                # касание

[plate2]
[plate2.bc]
type = "clamped"
[plate2.load]
type = "uniform"
q0 = 1.0
```

## discretization

`p` — степень Чебышёва по каждой оси (N = (p+1)² функций); `Q` — узлов
квадратуры Гаусса–Лежандра по каждой оси (маска ω > 0 отбирает внутренние);
`grid_n` — фоновая сетка для полей вывода и фигур.

Сетка вывода `grid_n` влияет ТОЛЬКО на вывод полей и фигур: числа решения
(w_max, реакция, комплементарность) считаются на узлах квадратуры и от
`grid_n` не зависят. Grid-зависима лишь ДИАГНОСТИКА топологии зоны
контакта (число связных компонент по сетке): при сравнении топологий
фиксируйте `grid_n`. Изменить сетку без правки файла: флаг
`plate-solve … --grid N`; программно — `solve(problem, grid_n=…)`,
`problem.with_discretization(grid_n=…)`; мгновенно после расчёта (без
повторного МОР) — `result.regrid(N)`.

## verify

`reference` — эталон: `analytic` (модельно-согласованная аналитика — circle,
annulus, point на круге, сертифицированный контакт), `mms` (изготовленное
решение — rectangle, circle; для `theory = ktn_full` — MMS ПОЛНОЙ КТН при
замороженных усилиях, см. ниже), `fem` (независимый scikit-fem), `none`.
`cross_1d` — дополнительная сверка
с 1D-Ритцем по радиусу (только осесимметричные постановки). `tol` — допуск
ворот. `model_gap` — печатать строку «истинный Кирхгоф» для документирования
модельной погрешности мягкого шарнира (NOTES §8); в допуск не входит.

Что покрывает `reference = "analytic"` (включая ФАБРИКУ автогенерации
с самосертификацией — plate_solver.analytic_auto; каждый эталон
проверяется подстановкой в уравнение и КУ, ряды — контролем остатка):

| Геометрия | КУ | Нагрузка | Эталон |
|---|---|---|---|
| circle | soft_hinge / clamped | uniform | замкнутые формулы |
| circle | soft_hinge / clamped | point в центре | замкнутые формулы (soft — модельный предел ν→1, NOTES §18) |
| annulus | soft_hinge / clamped (обе кромки) | uniform | система 4×4 |
| rectangle | soft_hinge или mixed все hinge | uniform | ряд Навье |
| rectangle | soft_hinge или mixed все hinge | patch (прямоугольная зона) | ряд Навье, замкнутые коэффициенты; сравнение в центре зоны |
| rectangle | soft_hinge или mixed все hinge | point (произвольная точка) | ряд Навье; сравнение в точке приложения |
| rectangle | mixed: hinge-пара + clamped-пара | uniform | ряд Леви (симметричный) |
| rectangle | mixed: hinge-пара + hinge/clamped кромки | uniform | ряд Леви, константы 4×4 на моду (фабрика) |
| rectangle | mixed: hinge-пара + free/clamped/hinge кромки (SFSF, SFCF, …) | uniform | ряд Леви-free: M_y = 0, V_y = 0 на модах (фабрика) |
| rectangle | mixed с free (консоль CFFF и др.) | uniform | fem: Кирхгоф (Морли), сравнение в точке свободной кромки |
| circle + контакт | soft_hinge / clamped | uniform (основание, скалярный Δ) | сертифицированный осесимметр. контакт Кирхгофа (плоская зона + кольцевая реакция); гейт — прогиб ВНЕ зоны, `w_max = Δ` тривиален; кромка `soft_hinge` (`w=Δw=0`) или `clamped` (`w=w'=0`); только `classic` |

Контакт: `analytic` доступен для круг + (`soft_hinge` | `clamped`) + `classic`
+ основание + скалярный `gap` (0 < Δ < w_free(0)); защемлённый круг ЖЁСТЧЕ
(`w_free(0) = q₀a⁴/64D` против `3q₀a⁴/64D` у шарнира), поэтому зазор меньше.
`ktn_linear` в контакте эталона НЕ имеет: КТН-поправка входит в лицевое условие
Синьорини (реакция гонится прогибом нижней лицевой), поэтому сходящаяся реакция
и базовое поле отклоняются от кирхгофовского с ростом толщины — классический
эталон годился бы лишь в тонком пределе (ложно-положителен при умеренной `h`);
корректный `ktn_linear`-эталон контакта требует теории-специфичной аналитики
(отложено). Полная КТН (`ktn_full`) и прочий контакт (не круг, силовой/зонный) —
ворота инвариантов (`reference = none`). Вне таблицы (L, compose, patch на
кривых зонах) — `mms` | `fem` | `none`: свободная граница контакта на
произвольной области замкнутых решений не имеет.

MMS полной КТН (`reference = "mms"` + `theory = "ktn_full"`, только `clamped`):
изготовленное решение при ЗАМОРОЖЕННЫХ мембранных усилиях `N̄` линеаризует
оператор и обращает сильную форму
`D Δ²w − (I − h_ψ²Δ)L(w) = (I − h_*²Δ)q` (`L = N̄:∇∇w`); линейный решатель
(`solve_fixed_forces`) на ТОЙ ЖЕ дискретизации воспроизводит `w_MMS` — единый
сертификат ВСЕХ членов сборки (изгиб, геом. жёсткость, член B `h_ψ²`, член A
`h_*²`). Прямоугольник (полиномиальная ω) ⇒ машинная точность; круг ⇒ ~1/Q
(маска). Это верификация ОПЕРАТОРА (замороженное `N̄` ≠ физическое `N(w)`;
нелинейная связь `N(w)` сертифицируется отдельно кармановскими эталонами и
редукционной лестницей R1–R5).

## eigen

Собственная задача (`eigenmodes.py`, v0.6.4) поверх ЛИНЕЙНОЙ сборки Ритца (те же
изгибная жёсткость/матрица масс, что в изгибе). `kind = "vibration"` — свободные
колебания `Kφ = ω²Mφ` (частоты `ω`, формы; `rho_h` — погонная масса ρh);
`kind = "buckling"` — потеря устойчивости `(K + λ K_geo(N⁰))φ = 0` под
равномерным мембранным усилием-эталоном `(Nx, Ny, Nxy)` (сжатие — отрицательный
знак; критическая нагрузка = `λ_cr·N⁰`). Анализ линейный (изгиб Кирхгофа), КУ
`clamped`/`soft_hinge`, любые R-области; `[load]`/`[contact]` не нужны.
`plate-solve` печатает таблицу значений и рисует формы (`_modes.png`);
`Result.eigen` — весь `EigenPair`. Верификация — классические эталоны Кирхгофа
(квадрат SSSS `k=4`; круг CCCC `N_cr·a²/D=14.68`), см. `tests/test_eigenmodes.py`.

```toml
[geometry]
kind = "circle"
a = 1.0
[bc]
type = "clamped"
[eigen]
kind = "buckling"        # buckling | vibration
Nx = -1.0                # равномерное радиальное сжатие (эталон)
Ny = -1.0
n_modes = 4
```

## Ошибки, FAIL и exit-коды

- **Ошибка схемы/несовместимость** — `CaseError` с шаблоном «ключ:
  получено X, ожидалось Y, см. docs/CASE_SCHEMA.md#секция»; CLI печатает
  её в stderr и возвращает exit 1. Это ошибки ПОСТАНОВКИ — исправляются
  правкой case-файла.
- **`plate-verify` FAIL** — постановка валидна и решена, но отличие от
  эталона превысило `verify.tol`: exit 1, таблица показывает rel по
  каждому эталону. Это сигнал о ТОЧНОСТИ (дискретизация мала, допуск
  нереалистичен или регресс метода).
- **exit 0** — решение получено; при `[verify]` — все гейтуемые эталоны
  в допуске.
- `plate-solve --check case.toml` — только валидация: exit 0/1 без
  расчёта (для пользовательских CI).
- Предупреждения (не ошибки) копятся в `Result.warnings` и печатаются
  CLI; например, скалярный `gap` при силовом режиме игнорируется.

Требование к зазору: Δ > 0 НА ОСНОВАНИИ (поле зазора обязано быть
строго положительным под зоной контакта; `gap = 0` допустим только
для пары пластин — касание срединных плоскостей).

## Оси, «верх/низ» и поверхности (сводная таблица)

Конвенция пакета: прогиб w > 0 и нагрузка q > 0 направлены ВНИЗ, ось z —
тоже вниз (NOTES §0/§19). Отсюда однозначно:

| Вопрос | Ответ |
|---|---|
| Куда действует q > 0 | вниз (на ВЕРХНЮЮ лицевую, z = −h/2) |
| Где основание/штамп | СНИЗУ (у нижней лицевой, z = +h/2); реакция r ≥ 0 действует вверх |
| Какая лицевая контактирует | нижняя (z = +h/2); при КТН-теориях (`ktn_linear`/`ktn_full`) зазор проверяется её прогибом (NOTES §21) |
| Что значит `sx_top`/`sx_bot` в fields.npz | напряжения на верхней (z = −h/2) / нижней (z = +h/2) лицевой; обжатие ν/(1−ν)·q_n на стороне давления |
| Что значит `w_top`/`w_bot`/`dh` в fields.npz | при КТН-теориях (`ktn_linear`/`ktn_full`): w_bot — прогиб контактирующей (нижней) лицевой по канону КТН (NOTES §21.1), w_top ≡ w (срединная), dh = w_bot − w — смещение контактирующей лицевой (в зоне dh < 0); classic/karman — все совпадают с w |
| Что выбирает `--surface` (CLI) | поверхность на w-фигуре: `mid` (срединная, по умолчанию) / `top` / `bottom` |
| Пара пластин | первая — ВЕРХНЯЯ (q⁻₁ = r), вторая — НИЖНЯЯ (q⁺₂ = r); поля второй — суффикс «2» |
| Физический контроль | в пролёте при q > 0: низ растянут (σ_bot > 0), верх сжат; в зоне контакта dh < 0 (обжатие) |
